Requisitos para completar la integración Workspace ↔ Bot

El Workspace MTA (workspace-mta.site) ya consume la API ERP v2.1 con ATTENDANCE_BOT_API_KEY. La conexión funciona: practicantes, jornadas, resumen mensual y ranking llegan bien. Este documento lista qué debe ampliarse o publicarse en el bot para reemplazar por completo el legado de Google Sheets y mostrar la misma riqueza en pantalla.

Resumen ejecutivo

P1 GET /horarios por practicante Tarjeta «Tu horario» deja de depender de Sheets
P1 discordUsername en practicantes Filtro admin y tabla alineados al nick de Discord

1. Consumidor (Workspace)

  • Cliente HTTP: Workspace/server/src/lib/attendance-bot-api.js
  • Mapeo UI: Workspace/server/src/lib/attendance-erp-mappers.js
  • Módulos: Asistencias (tabla + analítica), Notas (nota asistencia 20 %)
  • Auth: cabecera x-api-key (misma que BOT_API_KEY en Railway)
  • Zona horaria: America/Lima — fechas de jornada en calendario local
  • Periodo de prácticas: 2026-08-17 → 2026-12-10 (filtro desde/hasta en jornadas)

El Workspace no escribe marcaciones. Solo lectura. Cualquier alta/justificación sigue en Discord o MySQL del bot.

2. Matriz: qué funciona hoy

4. Convenciones de campos

Nombres

  • /jornadas y /practicantes: mantener camelCase (como hoy).
  • /resumen: puede seguir snake_case — el Workspace lee ambos.
  • No romper campos existentes; solo añadir los nuevos.

Enums ya mapeados en UI

Entrada: PUNTUAL, PUNTUAL_ANTICIPADO, TARDANZA, FUERA_DE_HORARIO, SIN_MARCA

Salida: PUNTUAL, SALIDA_ANTICIPADA, FUERA_DE_HORA_SALIDA, SIN_SALIDA

Jornada: ABIERTA, CERRADA, FALTA, LICENCIA, etc.

6. P1 — Horarios por practicante

Endpoint sugerido (hoy 404 según api-erp.html §9). El Workspace necesita bloques semanales para la tarjeta de horario y meta de horas.

Propuesta: GET /api/v1/practicantes/{id}/horario o GET /api/v1/horarios?practicante_id=

{
  "data": {
    "practicanteId": 14,
    "displayName": "zkingwolfx",
    "weeklyScheduledHours": 30,
    "blocks": [
      { "day": 1, "dayLabel": "Lunes", "start": "09:00", "end": "15:00", "hours": 6 },
      { "day": 2, "dayLabel": "Martes", "start": "09:00", "end": "15:00", "hours": 6 }
    ]
  }
}

day: 1 = Lunes … 5 = Viernes (igual que el bot en Discord). Si no hay horario personalizado, devolver el horario de área o el default del sistema.

7. P2 — Listado de marcaciones (alternativa)

Si preferís no duplicar horas en /jornadas, podéis exponer GET /api/v1/marcaciones con paginación. El Workspace podría hacer join por practicante_id + fecha + tipo (ENTRADA/SALIDA).

Opción B. La opción A (campos en jornada) es más simple y evita N+1 en el Workspace.

8. Ya integrado — Resumen mensual (Notas)

El Workspace lee GET /practicantes/{id}/resumen?periodo=mes para:

  • indicadores.nota → nota de asistencia del mes (peso 20 % en nota final)
  • indicadores.pct_asistencia → % en ficha de asistencia
  • indicadores.pct_puntualidad, pct_horas → analítica hero
  • horas.acumuladas, horas.semana, horas.meta_semana → gráficos semanales
  • ranking.posicion / ranking.total → chip ranking

No requiere cambios salvo que queráis exponer nota_mes histórica por mes cerrado (hoy el sync de meses pasados usa jornadas acumuladas).

9. Ya integrado — Ranking

GET /reportes/ranking?periodo=mes&criterio=asistencia&limite=20 — usado en vista admin (opcional) y contexto de equipo. Sin cambios requeridos.

10. Versionado y despliegue

  • Ampliar /jornadas es compatible hacia atrás (campos nuevos opcionales).
  • Recomendado: subir version en GET /api/v1 a 2.2.0 al publicar horas.
  • El Workspace no necesita redeploy obligatorio si solo añadís campos — el mapper ya los consume.
  • Probar con: curl -H "x-api-key: $KEY" "$BASE/api/v1/jornadas?desde=2026-09-01&hasta=2026-09-01&per_page=3"
